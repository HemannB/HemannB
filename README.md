## `whoami`

I got into technology because I wanted to understand how things are built, not merely use them.

Today, I work across the path between hardware and software: writing firmware, designing communication protocols, building configuration tools, creating user interfaces and integrating the upper layers that make the product usable.

> I like understanding the entire journey:
> **the signal entering a pin, the byte traveling through a protocol, the firmware making a decision and the result appearing on a screen.**

```text
electrical signal
       ↓
microcontroller
       ↓
C / C++ firmware
       ↓
communication protocol
       ↓
Python / C# application
       ↓
human-machine interface
```

This is where I like to work.

```text

ENS160 ─┼── ESP32 firmware ── API ── database ── dashboard
AHT21  ─┘
```

## `what_i_am_learning`

My current studies are increasingly focused on what happens beneath the abstractions:

```text
C language fundamentals
    ↓
memory, pointers and data representation
    ↓
microcontroller peripherals and registers
    ↓
communication protocols
    ↓
firmware architecture
    ↓
reliable embedded products
```

I am especially interested in:

* Embedded C and C++
* Microcontroller bring-up
* Serial communication and binary protocols
* Memory organization and bitwise operations
* Firmware architecture
* Hardware and software integration
* Debugging close to the metal
* Graphical interfaces for embedded and engineering systems
